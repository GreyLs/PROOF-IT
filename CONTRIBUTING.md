# Разработка PROOF-IT

Сопровождение: Arkady. Изменения связывают конкретный продуктовый сценарий с реализацией и проверяемым результатом.

1. Создать тематическую ветку от `main` и описать проблему, ожидаемое поведение и область изменения.
2. Сохранять lock-файлы. Изменения схемы БД оформлять новой SQL-миграцией; применённые миграции не переписывать.
3. Сохранять границы identity/role/ownership и private/public evidence. Проверять негативный доступ при изменении API или проекции доказательств.
4. Выполнить проверки из [инструкции](docs/GETTING_STARTED.md), соответствующие изменению. HTTP/UI-проверки требуют подготовленного стенда.
5. При изменении метода фиксировать протокол, выборку, seed, независимый контроль, ограничения и измерения. Синтетический результат не обозначать человеческой калибровкой.
6. Обновить OpenAPI, документацию и локализацию при изменении контракта. Проверка переводов использует контрольные суммы; устаревший QA manifest пересоздаётся по установленной процедуре.
7. Коммит описывает окончательный результат: `feat:`, `fix:`, `docs:`, `test:` или `chore:`. Проверить отсутствие секретов, рабочих БД и временных адресов.

В PR указать: триггер проблемы, новое поведение, выполненные проверки и оставшиеся ограничения. Протоколы сохранять без пересчёта исторических запусков в общую сумму.
